## 8. Surprises

- Temperature 1.0 was not the only interpretability problem: prior fallback would have leaked future val labels if the old function had been reused directly for validation. The cumulative fallback now obeys the same strict timestamp guard.
- Window selection is unstable across adjacent days; the report separates validation choice from exploratory test-best.
- Historical ALS used a test-selected fallback. Its applicability counts remain useful, but its full-test score is flagged rather than presented as a selection-clean model comparison.
- Coverage/Gini were implicitly measured at the largest requested cutoff (100), despite retrieving 200. This convention is preserved for comparability and now named explicitly.
- C3 versus C4 also changes history aggregation. It cannot establish a projection-only causal claim.
- CPU and CUDA inference of the same checkpoint produced slightly different rankings. The CPU C4 diagnostic is retained but excluded from the matched CUDA comparison.
- Both impression-cold pools contain some article IDs from raw training histories; counts are shown above. Unseen in prior impressions is not the same as first-ever novelty.
- The initial online-updating validation pass was causal but mismatched frozen-source test evaluation. Those diagnostic rows were marked superseded for selection and rerun with all validation labels held out.
- A duplicate configuration keyword failed the first baseline-selection attempt; the failed row was preserved.
- A small first-epoch loss decrease is not a convergence guarantee. Complete loss curves and the early-stopping epoch are retained, including any runs reaching the epoch ceiling.
